# Waggle · 蜂舞

> 人发布任务，Agent 执行，人确认交付。

Waggle 是一个面向人与 Agent 协作的本地终端任务工作台，使用 Python / Textual 构建。
目前以 Pi 为执行端，提供列表与看板视图，支持**目录路径提示、工作台内新建 Pi、明确接入已有 Pi、派发、进展、交付与人工验收**。
不读写原 Code Board，不修改 Herdr 核心、全局 Pi 配置或原快捷键。

## 为什么叫 Waggle

Waggle 来自蜜蜂的摇摆舞（waggle dance）。采集蜂回巢后，通过蜂舞传递花源线索，招募同伴参与采集。
蜂舞区是信息交流和招募的场所，而不是蜂后统一派单的指挥部。

这个名字强调的是**把人的任务意图传递给执行者，再把进展和交付带回来**：
Waggle 组织任务、记录轮次和展示反馈，Pi 负责具体执行，人决定派发、退回和验收。
蜂群只是协作的比喻：当前没有自动认领或调度任务，也不会自动批准权限或验收成果。

### 命名与升级边界

界面与代码统一使用 Waggle，命令为 `/waggle`，报告工具为 `waggle_report`，环境变量为 `WAGGLE_*`，项目加载入口为 `.pi/extensions/waggle.ts`。
**本次更名不保留旧名兼容，也不提供命名迁移工具。** 新默认数据目录为 `~/.local/state/waggle/`；不会自动寻找、搬迁或改写旧库和邮箱。
新目录没有数据时会显示空工作台，不代表旧数据被删除。旧环境变量、加载入口和事件前缀不再沿用；不能仅指定旧库路径就认为迁移完成。
已有工作请先在原版本完成并备份。等原 Pi 及其相关子任务结束后，手动停用此前的项目加载入口，再安装新入口并明确连接；不要同时加载两份桥接。
更名不修改运行中的 Pi、全局配置、Git 历史或远程仓库名称。下面的克隆命令使用你实际取得的仓库地址，不假定远程仓库已经改名。

### 已有轮次的显式只读观测

若当前库已保存原轮次，但运行中的 Pi 仍向另一处邮箱写进展，可在核对任务记录中的 Run ID 后，**只给这一轮**指定原邮箱根目录：

```bash
just run --observe-run '<原 Run UUID>' '/原邮箱根目录/bridges'
# 使用独立任务库时，同时保留 --db '/绝对路径/tasks.sqlite3'
```

这不是命名兼容或迁移工具：不扫描、复制、移动旧目录，不重载、重启或重新派发 Pi，也不转换协议/事件前缀。
读取会核对完整的原任务输入、Run、连接、Session 和精确目录；只接收已有解码器能够校验的快照，进展仍通过原有修订保护保存到当前库，不自动验收。
指定来源不会进入执行者发现列表，也不能用于派发或停止；界面标明“本轮只读接入”。需要停止时请到原 Pi 处理。
来源不可读、身份不符或心跳陈旧时保留最后记录并提示核实，不猜测完成，也不回退到其他邮箱。
旧桥接没有可选活动快照时仍显示“当前步骤未上报”，不伪造实时步骤或时间。

参数只对这次工作台进程有效，重开观察同一轮时须保留。结束的轮次不再改写，但未验收任务仍读取对应 Pi 的当前连接/会话状态；新轮次不继承单轮授权。
可重复指定不同轮次；同一轮次重复指定、未知/非当前轮次和演示模式均拒绝接入。

若原桥接已经支持下文的直接输入续接，并且你明确允许跟随这个任务而不只是一个轮次，改用：

```bash
just run --observe-task '<已知锚点 Run UUID>' '/原邮箱根目录/bridges'
```

只沿可验证的父子链接跟随，不扫描未知任务；每次最多补读八轮，落库成功后才继承只读路由。锚点可以是当前轮次，或本库已验证的祖先；重开仍须保留参数。派发、停止和发送补充始终禁用。`--observe-run` 不会自动升级为任务跟随；旧桥接没有这些链接时也不会猜测后续归属。
**已打开的工作台需先保存或复制未提交内容，再退出并按上述参数重开；无需操作原 Pi。**

## 开始试用

需要 Linux/macOS、Python ≥3.11、uv、just，以及支持 `agent_settled` 等扩展事件的 Pi。
Textual 固定为 8.2.8；首次缺缓存时 uv 需要下载依赖。

```bash
git clone '<仓库地址>' waggle
cd waggle
just run       # LOCAL：首次为空库，后续恢复已保存记录
just demo      # DEMO：12 个虚构内存样例；不打开数据库、不发现 Pi
```

1. 在工作台按 `p` → **添加真实项目目录**，填写名字和现有绝对目录。
   输入 `/` 或 `~/` 后自动提示目录；`↓` 选择、`Enter` 或点击填入，仍需 `Ctrl+Enter` 保存项目。
   支持中文、空格、非 Git 项目和仓库内子目录；保存时解析符号链接为真实路径，不回退到 Git 根目录或 HOME。
2. `n` 写任务，`e` 补充要求；创建/编辑均不会启动执行。
3. `a` → **新建 Pi**，或选择已经主动连接的 Pi；也可 `Ctrl+K` 搜索“新建 Pi”。
4. 新建窗口可选择 **新建并启动**：先核对任务范围、目录、名称和模型，确认后连接并分配成功就直接保存意图、派发本任务，无需返回再按 `s`。
   也可 **仅新建并连接**，连接后在同一窗口点击 **启动本任务**；原来的返回任务按 `s` → **保存意图并派发** 仍可用。
   **仅新建/分配不等于执行**；启动确认框默认“返回”，直接按 Enter 不会启动。
   这会按 Pi 现有权限执行真实工作，可能读写文件、运行命令和使用模型额度。
5. `g` 刷新进展，默认看本轮概览，点“展开详情”核对完整交付；“记录”只看关键变化，工具过程回原 Pi 查看。
   权限/交互提示仍需在 Pi 窗口处理；工作台不会自动回答或绕过确认。
6. Pi 必须提交完整 `waggle_report`，且本轮完全结束，才进入可验收状态。
   核实成果后按 `r` **人工验收**；阶段交付不能整任务验收。
   `b`：运行中仍补充当前轮；部分交付而无可审决策时，先选择本轮目的：**追问已有材料 / 索取可审提案 / 安排核查 / 申请新授权**。追问只要求解释已有问题与来源，索取提案要求完整可审材料；旧反馈默认不发送，需你勾选才作为待答问题；真实核查必须填写交付物、允许范围和验收依据。选择不派发，可仅保存；核对目录、Pi、完整请求和后果后才最终确认。

收集箱没有目录，不能新建 Pi 或派发。`Ctrl+K` 在空库时也能找到添加项目与新建 Pi。
已打开的工作台需 `Ctrl+Q` 后重新 `just run` 才加载新版；同一 Waggle 数据库内提交过的任务会恢复，退出工作台不会停止 Pi。
本次更名不会自动打开旧名目录中的数据库，切换前请先阅读上方“命名与升级边界”。

### 派发前先检查这条 Pi 连接能否接收要求

新版桥接生成独立的 **v2 `report-capabilities.json`**：绑定连接、会话、精确目录，比较 Pi 实际 `waggle_report` 的完整 schema，并记录实际调用入口、探测时间与归属保护边界。Fabric full-code 必须能经 `fabric_exec` 调用 `extensions.waggle_report`，并且 Fabric 描述的 schema 与原生注册一致；仅注册、在线、`typeof` 为函数或仓库源码已更新都不够。禁用捕获、白名单排除、隐藏工具、拒绝/过期的探测会阻止新请求，不新增旁路 provider 或放宽权限。

探测使用固定程序及随机、不匹配当前轮次的参数，不提交交付，也不制造模型消息。空会话返回 Pi 的“尚无 assistant 调用归属”保护回执时，只记录调用已抵达原生归属边界，**不是报告正文执行成功**；正式报告仍需正常权限、RUN_ID、补充覆盖和人工验收。心跳不能把旧探测续期。显式连接时用公开工具注册接口刷新捕获，消费派发/结构化补充前再次探测；不会靠重派任务修复通道。旧 v1 报告能力文件只证明注册，不能授权新版新请求。

- 新派发在保存 Run/决定意图前预检，发布前再查，Pi 消费时再次核对实际工具；提案和结构化反馈另需完整 `decisions`/`routing` 能力。运行中结构化反馈同样先查再保存。缺证明、身份不符、过期、工具隐藏或 schema 不兼容均不会自动发送或重试。
- 旧连接的 v1 心跳、历史报告、已发轮次和 Pi 原生直接输入/续接仍可读取；能力未知不等于旧任务失败，但不能再从新版工作台派发新请求。普通旧运行中补充的原有能力门保持。
- 首页显示 **检查连接**，不是再催一次提案：由使用该连接的人先保存未提交输入，核实旧执行及相关子任务已结束，再核对当前桥接加载路径、手动更新/重连。点按钮只有说明，不会重载、创建 Pi 或派发；源码已更新不代表运行实例已更新。
- 预检失败保留表单输入，不创建新 Run/决定意图；意图已经保存而发布未确认时仍保留唯一身份，只观察、不自动重试。本地保存不需要连接能力、不发送；草稿未确认，正式答复须经最后核对才形成确认记录。

### 失败进度与准备恢复（保存不是重试）

- 任务轮次、Pi 当前活动、观测新鲜度和 `bound/unbound/mismatch/unknown` 归属分开显示；Pi 忙碌、空闲或离线都不表示任务完成，独立聊天不被接管。
- “更多”或 `Ctrl+K` → **准备恢复草稿**：明确填写继续检查点、未完成工作和新合同，只保存，不创建 Run、不派发、不复活旧终态。旧错误和失败前最近真实报告仍可读，标为执行者自报，不能验收或成为正式批准来源。
- 原任务恢复只可选择明确核查/实施或原任务仅补证；独立成果盘点须新建 Task，不能借盘点验收原实施目标。仅补证保留原目标 `full` 禁止门，工具层并非硬只读沙箱。
- 真正开始新轮前，即使草稿已存成“待执行”，仍需原精确连接/会话的**新鲜、空闲且绑定原轮**观测，以及新目标的能力核验和最后确认。忙碌、离线、未归属、未知、只读观测或发布未确认时仅保存，不重派；旧人工解除记录也不能旁路当前活动检查。
- 来源身份/原始内容、目录或预览要求变化即失败并保留输入；新轮使用不同 Run ID。已保存意图但发布结果不明时只观察唯一身份，不自动重放下载、写入或试验。

能力诊断只读取既有严格 v2 证明，区分缺失、身份/schema 不兼容、入口未激活、缺功能及过期证明/探测。在线但不可报告不会被描述为完全未连接。v2 未提供 Fabric ref 缺失、探测拒绝/超时或原生 hook 失败的细分原因时明确为未知，不伪造原因、不索取凭据。
重开工作台只刷新展示，`/reload` 只刷新扩展、不保证刷新核心；疑似旧核心而缺公共版本证据时保留不确定性。任何 reload、重新连接或完整 Pi 进程刷新均由使用者另行决定，本页不执行、不盲目反复建议 reload。

### 决策单：先选意图，再核对后果

- 每项默认不选；先明确 **补业务事实 / 反馈追问 / 正式决定 / 等待材料**。只有当前意图的字段显示；业务“有条件”须写明边界，路径只作定位引用，不授访问许可。反馈可多行、最多 500 字，显示当前长度及超限原因，不必选择技术方案；普通备注不会变成业务事实。条件未填、全单混合不兼容意图或只读状态会说明为何不能提交；不会以简化界面为由放松验证。
- **保存草稿**没有确认；**确认但不发送**经汇总核对后形成带时间的本地确认记录，但零派发；**核对并发送**另列目标、来源、完整要求和副作用，最后确认才发送。返回、保存失败或来源变化保留输入。
- 历史事实/批准只作只读背景，不预填或自动沿用。非授权反馈只发送明确选定的问题；正式决定仍须整单材料齐备、逐项明确确认，混合事实/反馈须拆分。缺可信累计账本时不能正式批准预算。
- 旧问题选择显示完整问题、旧答复、报告来源和记录状态，默认不勾选；只有明确勾选项成为新一轮待答引用，不能变成旧许可重放。等待没有新材料不会重复派发。

### 主界面：先决定下一步，再阅读证据

新报告可带短 `handoff`：一行结果、一行阻碍、下一步责任/动作及现在是否需要用户输入或决定；这是平台展示合同，不构成权限或验收。未交齐提案/所选问题答复或材料未齐时，首页明确归执行者，不显示成等待你批准。没有新字段的旧终态报告用保守提示，不从专业文字猜联系人、原件存在或审批。技术原文、来源和核验限制保留在展开详情/全屏阅读；旧运行中和完整交付报告继续可读，原人工验收门不变。

- **顶部三行**保留品牌/模式与常用入口、当前项目/筛选、搜索/新建；不再用七行固定区域挤占正文。
- **按宽度切页**：≥100 列保留左侧约 32 列任务队列与右侧工作区；<100 列默认只显示任务列表，单击任务即打开占满工作区的详情页，键盘 ↑↓ 只移动选择、`→` / `Enter` 打开。详情顶部的“← 返回”或 Esc/← 回列表，保留筛选、搜索、选中任务及列表滚动；不是在列表上叠一个小弹窗。
- **极窄页头**：<60 列的列表顶部仅保留导航与动作入口；进入详情后改为返回、标题和动作入口。
- **固定操作栏**位于任务标题/状态下，左侧突出当前主按钮，必要时显示紧邻操作（如补充说明）；右侧常驻全屏阅读和“更多”。“更多”只列当前任务的记录、展开/收起详情、任务步骤；`Ctrl+K` 也保留这些入口。宽屏同排，窄屏操作在前、工具在后；40 列主操作优先，工具只占一行。标题独占一行，滚动长文不会把按钮卷走。可从正文用 `Shift+Tab` 返回操作栏。
- **步骤与权限分开**：部分交付无决策材料时先按“索取可审提案 b”；阻塞需核对由谁补原方案，再按“选择本轮目的 b”，旁边的“选择/新建 Pi”只预告下一步、尚不可点击；保存要求后才可选人或明确启动。已有执行者的待执行任务显示“更换执行者 a”，只进入选择器，不自动派发。决策单内完成汇总核对与确认，不从旁边按钮跳过审阅。验收前可点“核对报告”；执行待核实、停止/权限确认时，主按钮只叫“查看状态”，处理仍须到原 Pi。必要警告继续常驻。
- **下一步区域只解释原因**，不再重复按钮文字；仅待处理/待确认任务用警示色边线，正常执行或已验收维持中性色。短句说明“执行者先交可审提案／你暂不批准／可仅保存／确认后仅补证”及模型费用，避免窄屏长段断句。没有适用的紧邻操作时隐藏第二按钮。“更多”不会自动执行其列表项，步骤仍用独立表单本地维护，不把工具成功或图稿确认当作任务授权。
- **状态与主操作一致**：最新报告确有结构化决策单时优先按负责人路由显示“负责人待补材料 / 待你逐项决定”，正文前逐项列出问题、处理状态、建议或缺口；点击或选中后 Enter 定位到该项，不预选答案。正式决定显示为“已记录”，不冒充已执行。执行状态不明、权限等待和停止未确认始终优先核实。
- **部分交付**没有新决策项时显示“待执行者交提案”，主按钮为“索取可审提案 b”，而非催你批准。首屏标明“不能整任务验收”、本轮自报结果和下一步责任；技术待办在详情保留；本轮可选择追问已有材料或索取可审提案；输入框只写本次用户问题，系统核对清单与报告待办放只读参考区。旧反馈只有你逐条勾选才作为非授权待答问题进入请求。真实核查另需交付物、允许范围和验收依据，旧“继续”不能直接重派。提案轮若没有带 `routing` 且覆盖全部已勾选旧问题稳定 key 的当前 `decisions`，仍显示“提案未交 · 查看报告”，`d/b` 不把这份不齐的报告当可批准决策单；已有核证结果保留、不自动重派或催批准；材料齐备后再逐项决定。
- **正常执行**明确显示“暂不需要你操作”。底部只常驻必要的安全警告/只读提醒，不再重复一遍主要操作；普通报告刷新不重建未变化的事项列表，不抢其焦点或选中项。
- **待我验收**只列具备当前验收条件的任务。完整自报但条件未满足时显示“交付条件待核对”；最终仍须原有人工确认与保存前复核。
- **正文分层**对未齐交接先显示不可验收状态、本轮结果、卡点、谁做下一步及现在是否需要你；技术待办/依据和核验限制在展开详情/全屏阅读保留。信息缺失明确提示，不从耗时、工具成功或历史报告推断。
- **执行与连接**在本轮结束后默认折叠，正在执行时默认展开；可单独展开看轮次、活动与耗时。“展开详情”“全屏阅读”和“记录”仍保留完整原文、依据与历史。

布局与筛选都是展示投影，不改写任务历史，不自动派发、重试或验收。更新后须保存未提交内容并重开工作台，无需重启 Pi。

### 在 Pi 中直接操作同一任务

Waggle 不是唯一操作入口。新版桥接在已明确派发的任务之后，首次直接输入会用 Pi 原生选择框询问归属：

- **继续当前任务**：确认后持续关联，后续同任务输入不再逐句询问；Pi 页脚显示任务 ID 和解除命令。
- **独立输入（解除任务关联）**：正常交给 Pi，但不计入旧任务，也不会为了旧任务停止这段工作。
- **取消输入 / Esc**：本次不提交；交互模式将文本放回编辑器，附件请自行核对。

可随时用 `/waggle detach` 解除关联；它不停止 Pi 或派生进程。换任务应明确解除，不根据自由文本、相同会话或空闲状态猜归属。重载、重启、换会话及未授权的分支切换不继承关联。

同一轮仍在执行时，保留 Pi 原生文本、图片、模板及 steer/follow-up 行为，只记录输入接收事实，不重新发送该输入。此前交付失效，尚未接收的输入会阻止陈旧报告被当作最终交付。如果原生队列被清空或其他扩展吞掉输入，保持“待接收/需核实”，可核对后明确解除关联，不自动宣告完成。

原轮次已经结束时，**在原 Pi 中直接输入**会建立新的 Run UUID，并保存不可变父子链接；旧失败、报告和原始时间保留，不复活旧轮次，不重放原派发。这是 Pi 原生续接，不是工作台 `b` 的任务级仅补证请求。原要求、剩余事项及桥接已知未覆盖补充显式带入新轮；本地尚未发布的历史补充也不能靠换 Run ID 绕过验收，会在详情和下一轮补充表单中提示。

工作台分别显示**本轮结果**与 **Pi 当前活动**。未验收且仍有关联轮次的任务继续观察；空闲、结束、报告自报和人工验收不是同一件事。验收、退回、隐藏任务等提交前会重查已知续接与输入；验收弹窗不能接受确认期间换成的另一份报告。已验收、退回待派发、重新安排或隐藏的任务不因迟到回执自动重开。
工作台不会替只读来源撤销 Pi 内的关联；验收后做新工作，或改为在工作台重新安排时，请在 Pi 用 `/waggle detach` 解除旧关联，再按新任务/新要求继续。

关键记录只保存直接输入/续接事实，不复制整段聊天；原派发字段不偷偷改写，具体进展仍由 `waggle_report` 反馈。接入是当前连接内的明确授权，不是自动认领任意 Pi 历史。**旧运行实例不会热升级**：先核实旧执行及相关子任务已结束，再按接入步骤更新桥接、明确重连；已有失败轮次不据会话后续文字自动补造续接。不要为修复显示重派原任务。

### 全屏阅读长报告与宽表

在详情标题旁点 **全屏阅读**，或 `Ctrl+K` → **全屏阅读报告**。阅读页占满 Waggle 所在 pane，不再受详情栏宽度限制；不会替你缩放 Herdr 或改动其他 pane。

- 普通段落自动换行；Markdown 表格和代码块不压缩列宽，可拖动横向滚动条，或用 `Tab` 聚焦后按 `←→` 横移。长表还有独立的上下滚动，保留全部行。
- **查看原文**保留完整保存内容，默认不折行；需要时切换**原文折行**，也可返回排版阅读。排版不改写记录，不截取摘要。**复制全文**发送这份完整快照，包括正文、依据和要求，不是只复制屏幕内可见部分。
- 显示的是**打开时快照**：后台新进展不会打断当前阅读，返回后重新打开即可查看最新内容。`Esc` 或**返回**恢复原任务和滚动位置。
- 仅只读展示本轮正文、依据、剩余项、要求与补充；不派发、不验收、不触发工具，也不会打开报告中的网页或本地文件链接。没有本轮报告时明确提示，不拿上轮成果冒充。

本版不提供浏览器/HTML 导出；“全屏”仍以当前终端 pane 的大小为限。

### 复制只读文字

详情、任务记录、确认正文，以及全屏阅读中的段落、代码和只读原文，支持**按住鼠标左键拖选，松开后自动发送选区复制请求**。也保留 `Ctrl+C` 复制选区；可编辑表单仍使用 `Ctrl+C`，不在拖选时自动覆盖剪贴板。单击按钮、任务列表或滚动条不会复制旧选区。

排版表格使用独立滚动控件，不支持局部文字拖选；请点**查看原文**后选取所需片段，或用**复制全文**取得整份报告。复制不会修改内容、派发任务或触发验收。

复制使用 Textual 的原生 OSC 52 终端协议，沿终端/Herdr 链路传递。**发送请求不等于系统剪贴板确认成功**：若外层终端不支持或禁用了 OSC 52，自动复制、`Ctrl+C` 和“复制全文”都可能无法供其他应用粘贴。Waggle 不读取系统剪贴板、不自动调用宿主机剪贴板命令，也不绕过终端权限；这时需使用外层终端/Herdr 自己支持的手动复制方式。

### 分项决策单（d）

选中任务按 **d**，或点击操作栏 **决策单**。有结构化报告时，原“补充并处理”入口也会优先打开决策单，不必把多项选择重新拼成一段话。

- **逐项先操作，再读专业材料**：问题列表 ↑↓ 或单击切项，窄屏页头显示“第 X/Y 项”。含业务问题的未齐材料项在白话标题后先出现独立答复控件；80 列可直接选，40 列仍有“回答业务问题 ↓”跳转。第 2、4 类等负责人补证的事项可点“请负责人补证本项”：只临时选补证，不直接发送；“其他意见 ↓”仍可选暂缓、拒绝或非授权倾向。选“有条件”才显示条件框，空条件立刻提示；选“暂不确定”显示“无业务结论”。未齐材料的方案处理与专业缺口可按需展开；材料齐备可正式选择时，方案和风险仍先于回复。空白或“有条件”未填边界时，底部提交仍禁用；只写反馈而所有方案保持“未决定”时，底部主按钮明确变为可点的“提交反馈·仅核对”，项内按钮明确核对本单反馈，不必先选技术方案。仅保存与草稿仍可用。临时状态随输入更新；有修改时 Esc 打开保留编辑优先的关闭核对，明确放弃才关闭，不能把预览返回修改与丢弃混为一谈。
- **业务答案和技术方案分开**：只有当前报告明确提供独立的 `human_input`，才出现可答的业务问题；“有条件”须写明边界。D002 旧报告的白话业务问题只绑定原来源，新报告缺少 `human_input` 时不会沿用旧答案，也不从备注、选项或 Agent 推荐猜业务结论。可在不选择技术路线时给反馈、请求有依据的建议；文字、业务答案和技术倾向均不批准试验、文件修改、预算或路径访问。
- **保存与缺口归属要说清**：已确认但仅本地保存的意见标为“仅本地保存（未发送）”；已提交的补证意图仍需核实接收。临时状态不是已发送或授权，须经汇总核对才能确认/发送。旧报告只有事项级 `owner`，缺口未逐项分配责任，不能按关键词猜测谁应补；新报告逐项列明缺口、负责人和原始来源；点击“请解释”后，补证请求明确要求执行者用不带术语的话分别说明用户应回答什么、负责人应补什么依据，不代用户决定。材料齐备后仍需正式决定与汇总确认，不自动执行。
- **新报告把问题和证据分开**：新 `waggle_report.decisions` 每项必须带 `routing`，写明给用户回答业务事实、给用户审阅有据提案，还是等待负责人补证；用户业务事实必须有完整 `human_input`。建议只能是有来源、单位、适用条件、不确定性及签收状态的候选，或明确“证据不足、暂不能推荐具体值”。只等负责人证据的题不会成为正式方案选择。旧报告无 `routing` 仍可只读解析，不把旧文字伪装成已签收的建议。
- **没有新证据就等负责人**：补证后的新报告若同任务范围、同缺口/负责人/来源且依据未变，主板及决策单显示“等待负责人材料”；不会默认再次派发，但仍允许用户明确重新发送反馈。旧业务事实只在问题与完整任务范围相同时作为已确认的只读背景出现，新报告的答案保持空白，不自动沿用事实、技术批准或预算。
- **已存反馈待发 / 旧 Pi 离线**：主界面将最新同源的“未决定＋文字”标为“反馈仅保存 · 未发送”，下一步是打开决策单核对并明确提交；仅保存不会联系 Pi。旧轮已结束且原 Pi 仅心跳失效时，必须证实会话明确离线、没有新输入或续接，才可在提交时人工改选同目录可用 Pi，并在最终核对页确认。只读观测、执行未结束、身份或续接不明仍拒绝；改选 Pi 也不会自动取得负责人原始回执。
- **方案对照表**：两方案在 64 列及以上按「收益 / 代价 / 风险 / 范围」横向逐行比较；更窄的屏幕或超过两方案时，每个方案分别用字段/内容双列表格展示，文字换行、不横向截断。边框与交替底色帮助逐行核对；数据仍为 Agent 自报，不等于批准。
- **预算三项并列核对**：显示已结构化确认的旧总帽（不是剩余额度）、累计已用量以及本次建议上限。没有可靠结构化旧账本与已用量时明确“未知”，不从普通文字猜数、不提供正式预算批准输入；即使 Agent 自称材料完整，也只能请求补齐账本、暂缓或拒绝。建议不会预填为批准。若确需授权新累计额度，须先建立可核对的旧帽/消耗事实；**累计账本现可在独立页面记录与人工核验，但正式预算批准入口仍关闭，不可在决策单完成**。真实证据与启用门须独立通过；可先要求补证或暂缓，旧预算不会自动续到补证轮。
- 支持方案选择、批准/拒绝、预算上限和偏好；也可要求补齐、暂缓或保留未决定。推荐不自动勾选，预算输入不预填，偏好不构成权限。
- 材料不足时，选项只允许表达**倾向（非授权）**、要求补证、暂缓或拒绝，不能正式选择/批准/填写执行预算；未决定仍默认不授权。Agent 的推荐和自然语言解释不能代答。所有材料均属 Agent 自报，需人工核实。

| 操作 | 含义 |
|---|---|
| **提交补证请求 / 确认并继续** | 任一项缺材料、或预算旧帽/用量未结构化核实，只能提交补证请求：在原“继续”路径中至少有一处独立业务答案、要求补证或非授权倾向，**不能混入正式批准或回捞旧授权**；仍核对原会话/目录和完整文字再明确发送。补证新轮不继承上轮自由文本中的许可、预算或待执行命令；原轮记录仍保留。补证轮不能以 `full` 宣告整任务完成，Pi 和工作台均拒绝这类报告，须把原任务未完成事项明确留下。全部可授权事项材料齐备且无未知预算后才显示“确认并继续”，仍沿原派发与 Pi 权限确认，不需再按 `s` |

按钮按常用操作优先：提交/处理在左首位，其次仅保存、草稿，返回在末尾。新建 Pi 的“新建并启动”、本轮补充“提交到当前执行”同样排在前面；这只是位置调整，不会代替二次核对。最终确认窗口的“返回”仍为默认焦点，直接按 Enter 不会提交。追问/提案的自然预览中 Ctrl+Enter 只提示尚未发送，最后须明确点击发送按钮或移到该按钮后按 Enter；编辑页 Ctrl+Enter 仍只打开核对页。

所有操作都有汇总核对页：先列各项业务答案、方案状态和本次只保存／仅补证／可执行的后果。正式方案在这里直接显示风险、代价和排除；多项核对页会提示总项数及向下滚动查看剩余项，40 列不会把首屏当作全部。完整原文、连接和报告来源仍可展开。默认聚焦“返回修改”，按 Enter 不会提交。需要执行者时可在同一流程选择或新建；新建仅连接，返回后仍需核对决策内容，不能把创建 Agent 当成执行同意。

此前正式决定仅作只读历史，不自动沿用；正式处理须显式重新选择整单。旧预算因累计消耗未知不回捞。原任务、目录、本轮要求或剩余事项变化后须重新决定。补证轮只传缺口、反馈和非授权倾向，既不重置预算，也不把旧轮执行要求作为新许可；消耗不明须先核实。预算是提交给执行者的范围约束和停止条件，不是计费/时长的强制熔断器，Pi 的原权限确认仍保留。

决定记录与 Run/补充意图在同一事务保存后才发布。**已保存 ≠ 已发送 ≠ 已执行 ≠ 已验收**；发布结果不确定时保留原意图、不自动重试。材料、会话、任务或确认窗口变化会拒绝过期提交。`Ctrl+K → 决策记录` 可只读核对历史；问题解决且新报告不再包含决策单时，`d` 也直接查看历史，不再次催你决定。已验收、归档和回收站任务不能追加决定。

最新报告没有结构化决策项时，不把旧文本猜成批准，也不在首屏展示误导性的决策横幅；若已有历史决定，`d` 只读查看历史。完全没有决定记录而确需整理材料时，`d` 才提示缺失并提供一份可编辑的“请补齐决策材料”请求，经原有补充/派发确认后才发送。不会因此自动启动真实任务。新版桥接须在旧任务及相关后台工作结束后，按原接入方式明确加载；运行中的 Pi 不会自动热升级。

报告工具的可选 `decisions` 为 1～6 项，未需要决定时直接省略（不传空数组或 null）。每项使用稳定任务内 `key`，`kind` 为 `choice` / `approval` / `budget` / `preference`，提供 `question`、`why`、`owner`、`evidence`、`missing`、`scope`、`risk`、`cost`、`options`、`recommendation`、`reason`、`exclusions`、`budget`，以及可选的独立业务问题 `human_input`（choice 的键/标签或 text 问题）。**新生成的决策报告**每项还须带 `routing`：`audience`（`user_fact` / `user_decision` / `owner_evidence`）、与 `missing` 逐项匹配的 `evidence_needs`（缺口、负责人、来源）和 `advice`（`supported` / `insufficient`，值/单位/条件/引用/未知项/负责人签收）。缺证不猜值，候选不等于批准。预算使用次数/分钟/MiB 非负整数和停止条件；`full` 报告不能同时夹带待决定项。旧版报告/决定保持原字段与版本，含业务答案的旧人工决定仍为版本 2；带新角色合同的决定采用版本 3；每任务最多保留 128 份不可改写记录，不自动删除旧授权证据。

### 成果库存与独立人工核验

`更多 → 成果库存` 或 `Ctrl+K → 成果库存` 可查看、明确选取旧成果及人工事实；保存不发送、不启动。

- 来源默认未选。只引用规范已验收报告的**明确选定字段**，或实际人工确认的业务答案；绑定原 Task/Run、报告修订、原始内容摘要及人工验收/决定锚点。不会搜索 Pi 聊天、扫描目录，也不从备注或技术批准猜事实。
- 执行者自报、平台任务验收和原件核验是不同证据等级。原件定位是用户填写的线索，不是路径可访问/存在或访问许可；未核实显示未核实，不假装文件缺失。旧收益、名单和测试不能变成新目标的正式成果。
- 人工核验另有默认未选的结果和最后确认：明确核验人、实际方法与 UTC 时间、覆盖边界、缺口及下一责任。平台只保存人工陈述，不保证核验人身份或原件已被机器探测；未知材料/联系人如实填写未知。核验记录追加，不覆盖旧记录。
- 历史事实只属于原问题与原范围，冲突答案连同原记录保留并显式提示；不自动填入新问题、不继承技术批准。引用与核验均不是新实施、路径或预算许可，不能解除预算未知门。
- 已保存的显式引用会在后续完整派发预览中作为非授权数据导出；预检、实际 Run 和邮箱使用相同文字，前序来源/库存各只有一个规范尾部。填写或最后确认时来源变化、写盘失败或合同与引用合计超过 6000 字，拒绝保存/派发并保留输入，不截断审计。
- 引用任务可归档，仍被引用的来源不能永久删除；删除引用所属任务时同时清理它的库存及核验记录。无持久化 Store 的会话明确标为退出即丢失，不称为已经落库。

### 独立累计预算账本（正式批准仍关闭）

`更多 → 累计预算账本` 或 `Ctrl+K → 累计预算账本` 独立于业务答案 / 反馈页。可声明稳定资源范围、记录原始回执、明确核验完整覆盖或撤销已有记录；选择与数值默认空，最终核对默认返回。保存只写本地审计，不扫描原件、不读取填入路径、不分配、不派发、不发送停止命令。错误或来源变化保留输入。

- `BudgetScope` 的稳定资源标识、单一计量来源、起点和定义不可改写；新 Task / Run、重连、provider 切换或删除任务都不清零。相同资源标识不能另建范围。计量定义由人明确说明，**不是平台验证的全机器统一资源 ID**；不得用别名绕过旧累计用量。
- 只接受累计次数 / 分钟 / MiB 的非负整数，不推算其他费用、GB、旧倾向或未记录历史。累计用量必须引用先前保存的精确 N4 证据，并单独明确人工完整核验。身份文字不是认证，已验收报告与执行者自报不会自动成为可信计量。
- 同一回执内容一致是幂等操作；回执身份 / 并发修订冲突、倒退数字、缺来源或不覆盖全部起点至核验时刻时显示 `unknown`，不是零，也不能正式续用。v1 的冲突不会通过选择较大修订静默消失。现阶段没有可信执行器回执适配器或自动计量。
- 域内已有保存授权只记录**同一范围新累计总帽**与核验摘要、停止条件、记录人、时间和取代 / 撤销链；可核对余额仅为总帽减完整核验的累计已用，绝非新增增量。新回执 / 核验 / 来源漂移会使旧记录失效；审计不能删除、重排、回退，恢复旧文字不能复活旧 grant。删除来源留下历史数字但余额重新 unknown。
- **正式累计预算批准按钮与业务预算确认均保持关闭**，即使本地人工核验记录完整。纯域保存授权机制仅在隔离测试中验证，真实材料和正式启用仍需独立证据门。保存授权、派发许可与实际用量是三件事；UI 数字不承诺执行器、工具、时长或文件系统的强制熔断。
- schema 12 从 v1–v11 保留精确原始备份和修订，只新增空预算注册表，绝不迁移自然语言预算为 scope / 用量 / grant。源码测试仅使用一次性库；本文不表示真实用户库已迁移或正式功能已部署。

### 局部依赖与明确单写者交接

`更多 → 局部依赖` 或 `Ctrl+K → 局部依赖` 只保存声明和人工核对，不自动分配或调度。来源、类型、证明等级、操作及接续者默认未选，最后确认默认返回；写盘失败或来源漂移保留输入。

- 依赖分契约、证据与写冲突，明确究竟阻塞成果盘点、原任务补证还是实施。写冲突只针对实施及逐条填写的相对文件定位，不锁住无关只读盘点/补证。未知自由文字保守视为可能实施；写“只读”或补证前缀不能绕过门，规范合同与真实确认的结构化补证分别校验。
- 条件不会因来源任务验收而自动满足。契约条件须另存人工核对；证据条件须明确选择匹配来源的已保存库存项，并区分“已验收报告”与“明确人工原件核验”。后者缺核验、冲突或来源改变时拒绝相应执行，报告验收不能替代原件核验。
- 写冲突须**先单独保存原写者释放，再单独保存接续者接收**。释放绑定原 Task/Run/Pi/会话、原始来源摘要、同一精确目录、接续 Pi、逐条文件范围及 UTC 实际核对/到期时间；接收必须独立填写并匹配最新释放。仅有释放、过期、目标/合同/目录/文件扩大或来源改变均不可接管，旧接收不自动恢复。重新声明同类型来源/范围保留旧审计并重新核对。
- 人工核对、释放和接收是明确人工陈述，身份未认证，平台未探测原件、符号链接或文件写者。共享文件实施的新分配/派发还要求原 Pi **新鲜空闲且精确归属原会话/轮次**，接续 Pi 也须新鲜空闲且目录一致；离线、空闲或已验收都不是释放。Pi 主回合空闲也不证明派生进程已退出，需要人核对释放来源。
- 已保存 Run 的身份与请求不可删除或改写，已结束轮次及交付原文只读。合法未启动目标/合同、来源或证据变更时，平台在同一事务追加**永久失效**记录；它只撤销旧证明的可用性，不是人工确认或新许可。把文字恢复原样也不恢复旧释放/接收；必须重新声明、释放与独立接收。失败写盘不发布失效记录，旧数据与输入保持原状。
- 未持久化记录明确显示“尚未交接”，不用于真实接管；无法核对仍可先保存待补材料。循环依赖拒绝，审计不删除/覆写/重排；仍被引用的来源不能永久删除或使项目目录失效，清除所属任务同时清理它的依赖及交接审计。
- 明确记录作为非授权引用数据出现在完整请求预览中，预检/Run/邮箱文字一致，完整合同与全部审计超过 6000 字会拒绝而不截断。这是平台分配/派发前规则，**不是执行器文件锁、工具只读沙箱、原子跨进程所有权转移或跨工作树调度保证**；Pi 原有权限确认仍保留。

### 统一补充说明（b）

详情中的 **补充说明 b** 或 Ctrl+K 使用同一入口，根据本轮的已确认状态分流，不把失联当成结束：

| 状态 | 动作 |
|---|---|
| 未派发的待安排/待执行任务 | 填写新要求；“仅保存”只落本地，“提交并核对”在最终确认精确目标后才派发 |
| 已确认 working、仍精确绑定且可控制的 Pi | “提交到当前执行”进入发送核对，确认框默认返回；不另建轮次 |
| 部分交付且当前无决策单 | “索取可审提案 b”先列现有依据、缺口/负责人、已用量和预算原件；旧反馈零默认选择。仅保存不执行，最终确认后才发仅补证新 Run |
| 已结束且阻塞 | “选择本轮目的 b”先核对所缺原方案/范围由谁提供；不能从阻塞文本猜负责人或自动重派 |
| 排队、权限等待、停止未确认、失联、归属失效或压缩交接 | 不降级到下一轮；核实原 Pi，必要时稍后重试 |

已结束任务先核对交接责任。**追问已有材料**只解释用户问题与来源，不能从答复生成新的正式方案批准；已选择的旧问题仍须由当前同 key 的结构化答复逐项回应。**索取可审提案**将本次用户要求及你勾选的旧问题编为仅补证 Run，系统交接清单只读展示，要求执行者用现有 `decisions.routing/evidence_needs/advice` 说明证据、缺口、负责人、已用量/新预算原件与需你决定的事项；旧反馈和当前报告待办只作注明来源的背景，不是新授权；已勾选旧问题带来源稳定 key，Agent 须在当前提案逐项同 key 回应，不能用无关决策冒充答复。无原件须写未知，不猜预算；该轮不能用 `full` 冒充整任务完成。它可能读取已有材料并消耗模型额度，**不是工具级强制只读**，Pi 权限请求仍须逐项核对。**安排核查**必须逐项写本轮交付物、允许范围及验收依据，可能读写/运行命令；旧仅写“继续”的待派发要求须先补齐合同。**申请新授权**仍只列提案材料，不批准新试验或预算。

表单显示任务、精确目录、执行者及会话、原始范围和仅供参考的旧报告。点击“提交并核对”先打开返回修改优先的自然预览：明确所属任务，并按“针对的问题 → 问题来源 → 本次内容”逐项对照，再核对接收方/精确目录、后果和费用未知。只有明确勾选的稳定旧问题引用才显示为已关联；零勾选时明确标为独立新追问／要求，不能靠文字相似性猜回复对象。多个关联项对应同一段自由文字时，每项标为共同追问／补充，不能伪装成独立的逐项答复，实际发送文字仍只编译一次。来源显示原任务、原报告版本、原项序与记录时间，不把显示顺序当成原问题序号；此前用户反馈放折叠的只读参考，不能与本次内容混淆。当前决策单汇总同样将原问题及报告项来源与真实本次业务／正式答复相邻展示，业务答案对照其独立业务问题，不冒充技术方案选择。未选数量、协议 key、完整发送原文和连接来源仍可核对，来自同一已检查快照。确认后才保存并派发。若没有可用执行者，先保存输入，再在同一流程选择/新建并核对目标；无需返回按 `s`。仅保存不派发；已存追问/提案分别标“核对已存追问 s / 核对已存提案 s”，均尚未发送。按 `b` 可重开编辑，只恢复可完整重编译且匹配当前来源的用户文字及明确保存的勾选项；来源未知、变化或格式含糊时保留完整只读原文，重新填写与勾选，不从自由文字推断许可。按 `s` 仍须最后确认；仅补证围栏不因保存恢复而变成批准。收集箱须先明确真实目录，不猜测执行位置。

已结束任务的下一轮窗口把**当前报告的结果与待处理事项（执行者自报）**、同任务稳定范围内最近一次已确认的**非授权人工反馈**放在可滚动的只读参考区；旧问题选择器只显示问题标题，并常驻选中数及选中问题摘要；此前用户反馈、完整来源和投递状态放只读详情。窄屏可滚动读完整原文，提交／仅保存／关闭始终可见。提案草稿可引用本轮待办作为标明“执行者自报”的非授权背景；旧反馈未勾选不进入新请求，勾选也只成为待答问题，不继承旧正式选择或预算；完整新请求仍须在发送前核对。此前未确认覆盖的补充仍按原规则单独提示核对，不从报告猜授权。

**长度与完整请求**：追问／提案本次正文与所选旧问题引用共用 4500 字符额度；安排核查的交付物、允许范围、验收依据各限 1800。输入旁显示当前长度、旧引用占用以及同一合同编译器计算的完整请求／剩余额度；前序已验收材料、库存与依赖等已认证引用也计入 6000 的完整请求上限。来源或内容无法合法编译时明确显示“暂不可核对”，不把未知当 0，不截断原文或边界。范围／验收字段有自己的计数与必填原因。完整错误位于可聚焦、可用 Home／End／PageUp／PageDown 阅读的滚动区；缩放保留异步错误，实际编辑或明确再提交才重新核对。

**真实处理阶段**：显示核对来源、目标与能力、等待最后确认、本地保存意图、发布请求等实际步骤，不显示猜测的百分比或预计耗时。核对／发布过程中输入只读、提交与关闭受保护；失败后的输入和完整原因仍可查看。阶段文字不代表保存、发布或接收已经成功。

已确认的执行者可用时，补充要求和新 Run 意图在同一事务提交成功后才发布。保存失败保留输入且不派发；发布结果不确定时保留同一 Run，仅观察，不自动重试。任务、目录、会话、原 Pi 新输入或续接变化会阻止过期提交。只读观测不能由主按钮升级为执行控制，可保留仅保存操作。

**持续结果区**：任务详情保留可核对的草稿／确认仅保存、请求已发布等待接收、发布未确认、Pi 已接收、执行者自报与人工验收的区别，不只依赖短暂通知。仅本地排队意图不能证明发布；只有本工作台成功发布且精确身份仍匹配，才显示这一会话的发布已知。重开工作台不继承这个临时成功标记；无有效原接收回执时仍标未确认，绝不自动重发。报告自报与补充覆盖不能代替人工验收；验收原记录须匹配当前来源和修订，来源不符、未来修订或原报告缺失均要求核对。模拟与未持久化会话也会明确标注，界面提示不生成新授权。

已验收任务保持验收结果，后续工作另建任务；归档/回收站任务须先恢复。模拟执行仍是明确标注的本地模拟补充，不接入真实 Pi。

运行中补充最多 4000 字符、每轮最多 16 条，同一轮只允许一条等待接收确认的意图。先保存本地意图，再发布带原 Run/Agent/Session/目录及完整派发身份的独立请求。
Pi 使用原生 steering 消息在可处理点接收，不模拟键盘、不强制打断当前工具，也不代答权限确认；重大目标或目录变更仍应结束旧轮次后重新安排。

状态区区分等待确认、已排队、Pi 已接收、未被接收及报告自报覆盖；**发布不等于接收，接收不等于执行，覆盖仍是自报而非人工验收**。
补充意图与回执单独持久保存，状态变化也进入本轮关键记录。即使关键事件被裁剪，详情、验收窗口和记录的轮次标题仍可查看完整补充正文；历史报告叶节点仍是当时快照，不被最新补充状态改写。
原派发要求不覆盖；已有完整报告会失效，后续 waggle_report 必须携带最新收到的 supplement_id。
有任何本轮意图尚未确认被最终报告覆盖时不能验收，包括投递失败/未知/拒绝。确认结束后，可在下一轮表单中核对这些未覆盖内容，再明确保存下一轮要求。

同一补充 ID 不重复注入，重开窗口不自动重发。请求须在 30 秒内进入 Pi 队列；这不是当前工具必须在 30 秒内完成的承诺。

覆盖真实 Pi 离线 steering/回执/多条补充/重复请求、陈旧报告拒绝、收到补充后的压缩续接、归属失效过滤、投递/存储失败、旧桥接与只读来源拒绝、终态迟到回执，以及预检期间任务结束并永久删除的竞态；没有操作真实任务库或运行中的 Pi。

### 执行中概览与耗时

执行中概览展示最近自报的具体进展、阶段结果、剩余工作/下一步和需处理的问题，不再只提示展开详情。
有匹配的结构化简报时使用其行动、结果和核验说明；否则保留本轮报告原文，可滚动阅读，不截掉成果或限制。
没有简报核验说明时，仅标明已上报的依据条数；完整路径、哈希和依据仍在详情中。自报和心跳都不等于独立验证，也不能证明任务没有卡住。

- **本轮历时**：从本轮保存派发意图起计算；该记录缺失时使用本轮确认开始时间，并标明起点。包含排队、人工等待等墙钟时间，**不是模型/CPU 实际工作耗时**，也不是整个任务跨轮次累计耗时。
- **距最近报告**：按本轮修订顺序取最后一条带时间的执行者报告，不用心跳或文件修改时间代替报告时间；不据此推断当前正在做什么或预计何时完成。
- 本轮结束后按对应结束记录冻结历时；人工解除只计算到解除记录，不冒充 Pi 的实际停止时间。缺起点/结束时间、旧记录没有可识别时间或出现时间异常时显示“时间未知”，不从打开工作台时重新计时。
- 时长刷新只更新状态区，不改报告、数据库、验收状态或已展开内容的滚动位置。运行中的 Pi 无需重载；工作台仍需保存未提交内容后重开才能加载新版。

### Herdr 中的鼠标兼容

在 Herdr 内（`HERDR_ENV=1`），Waggle 默认设置 `TEXTUAL_SMOOTH_SCROLL=0`，使用字符坐标鼠标模式，
避免 Textual 的像素坐标协商与 Herdr 输入转发不一致时，点击任务区却落到左上角导航。
普通点击、滚轮和窗口调整仍可使用；Herdr 外保持 Textual 默认行为，已有的显式环境变量设置也不会被覆盖。
若曾强制开启平滑滚动，可用 `TEXTUAL_SMOOTH_SCROLL=0 just run` 启动（保留原来的 `--db` 等参数）。
此设置不修改全局配置；只需重开工作台，不需要重启或重新加载 Pi。

### 路径提示的范围

只读取输入对应的一层目录，不递归扫描、不读取文件内容、不列出普通文件。
每次最多检查 1000 个目录项、显示 12 个候选；目录很大时请直接输入更完整路径。
完整目录会先提示带 `/` 的路径，填入后可继续选择子目录；输入 `/.` 才显示隐藏目录。
空输入、相对路径不会默认浏览 HOME。提示异步防抖，不覆盖输入、不自动保存；旧结果不会替换新查询。
无权限或无匹配时可继续手动输入，保存仍会校验真实目录；网络挂载的实际读取耗时由文件系统决定。

## 明确接入 Pi

### 工作台内新建 Pi（在 Herdr 中使用）

1. 选择真实项目下的任务，按 `a` → **新建 Pi**；也可 `Ctrl+K` → **新建 Pi**。
2. 核对精确目录和名称：默认取关联任务标题（最多 80 字符），无关联任务时保留 `Pi · 项目目录名`，可手动修改；模型可留空使用 Pi 配置，或填写 `provider/model`。
3. 选择 **仅新建并连接**（`Ctrl+Enter`），或点击 **新建并启动**。后者先展示完整任务要求供你明确确认，确认后连接和分配成功即派发，不必返回再按 `s`。
   快捷启动只对已选中、尚未启动的待安排/待执行任务提供；没有可派发任务时只新建连接，不猜测要运行什么。
   两种方式均新建独立 Herdr 标签页和 Pi 会话，工作台焦点保持原位。
   Pi 会话名与新 pane 的 `label` 使用同一名称，标签页名为 `Pi · 名称 · 创建 ID 前 8 位`；不改 pane 身份、目录、权限或运行状态。以后编辑任务标题不会自动重命名已有 Pi、标签页或 pane。
   无需安装项目入口、输入 `/waggle connect` 或接管已有会话。
4. 项目信任、工具权限或模型认证仍在新 Pi 标签页处理，不自动批准。
   仅新建时，显示“Pi 已连接”后，未改变的待安排/待执行任务会自动分配；可直接点 **启动本任务** 核对并派发，也可返回后再按 `s`。
   已确认“新建并启动”时，请求发布后自动返回任务，仍需等待 Pi 接收回执；发布请求不代表执行或交付完成。
   若没有关联任务、任务已变化或保存分配失败，不会派发；稍后用 `a` 选择已创建的 Pi，无需重复新建。

创建按钮提交后不会重复启动；“刷新连接”只读取状态。等待连接期间返回或关闭工作台，会取消尚未发生的派发，但不会退出已经创建的 Pi。
任务、目录、会话身份或空闲状态变化会阻止快捷派发；派发前先持久化意图。派发未确认时保留原轮次，只观察、不自动重试。
新 pane 的名称和归属须经 Herdr 确认后才提交 Pi 启动命令；命名失败或回执不符会保留已知标签页/pane 信息，停止后续启动，不自动重试或删除标签页。
超时或错误可能意味着标签页/Pi 已创建；请先核实显示的标签页和创建 ID，切勿反复新建。
创建意图和已知标签页/Pane 位于邮箱的 `launches/<创建 ID>/launch.json`；重开工作台不重放创建命令。
自动连接授权只适用于这一个新会话和精确目录，10 分钟有效且只能使用一次。
过期、重启、换会话或 `/reload` 后，可在 Pi 中重新 `/waggle connect` 并明确确认，不复用旧授权。

此入口需要安装 Herdr 和 Pi，并在 Herdr 内运行工作台。外部终端仍可使用下面的 `just pi`。
不创建后台守护服务，不改全局配置，不复制 API 密钥到启动参数。

### 已有 Pi：安装项目级加载入口

在**工作台目录**的另一个终端运行：

```bash
just install-bridge '/你的精确项目目录'
```

然后回到这个目录中的 Pi：

```text
/reload
/waggle connect
```

确认弹窗会列出精确目录和会话，说明工作台可派发任务、停止其派发的执行。
只有确认之后，该 Pi 才会被工作台发现。不会仅凭“终端空闲”接管会话。

安装命令只新增项目 `.pi/extensions/waggle.ts`，引用此工作台的 `pi-bridge.ts`。
不同内容的同名文件或符号链接会拒绝覆盖；相同入口可重复检查。
安装、手动启动和工作台新建 Pi 都会检查已知旧入口 `.pi/extensions/taskroom.ts`；若仍存在，会在写创建授权或新建标签页之前拒绝，避免与显式加载的桥接重复注册。
请先核实旧执行已结束，将旧入口备份移出自动加载的 `.pi/extensions` 目录，再明确重试；程序不自动搬迁、不覆盖入口，也不通过禁用全部扩展来绕过冲突。
不修改 `settings.json` 或全局扩展。**Pi 仍须信任该项目，才会加载项目入口。**
若 `/reload` 后没有 `/waggle`（项目未受信任，或禁用了项目扩展），可用下一种显式 `-e` 启动方式；
工作台不会改信任配置或替你批准项目。若你自行调整 Pi 项目信任，请按 Pi 提示重启后再连接。
工作台目录移动后需自行更新入口；不要在真实任务运行中 `/reload`。
从旧原型目录切换到本仓库时，已有入口仍引用旧目录，不会自动改写。
保留旧目录和正在运行的会话，待相关任务结束后再核对并手动更新入口；克隆仓库不会迁移运行数据。

### 从终端手动新开 Pi：不安装任何项目文件

```bash
just pi '/你的精确项目目录'
# 可转发普通 Pi 参数，例如：
just pi '/你的精确项目目录' --continue
```

这是普通交互式 Pi，通过 `-e` 加载桥接扩展；不加自动批准参数，也不自动连接。
启动后同样需要 `/waggle connect` 并确认。

每次重启、换会话或 `/reload` 都会撤销旧连接，需要重新明确连接。
旧任务不会自动转交新连接；结束旧轮次后，用 `a` 重新分配。
Pi 本轮完全结束后可 `/waggle disconnect`，不会退出 Pi 本身。

## 上下文压缩与续接

支持已核验的 `pi-context` 同会话压缩交接：`context_compact` 返回成功回执后，
短暂的 Pi 中断/空闲不会结束 Waggle 轮次。桥接核对本次工具回执、摘要分支及续接通知，
继续使用原 Run ID；不重新派发、不重复执行、不自动验收。
普通响应错误、人工停止和额外输入仍保留原有保护，不会一律忽略 `aborted`。

- 压缩取消或失败，仅在确认仍属原分支时继续关联；不匹配的交接会暂停桥接。
- 缺少续接通知时保留“尚未确认结束”，不按超时猜测完成，也不自动重派。
- 交接期间无法安全取消外部扩展的待续接回调，停止请求会明确显示**尚未执行**。
  请在 Pi 核实，续接后再次明确停止；长期没有续接时，先核实并结束旧 Pi，再按失联恢复处理。
- 与本轮无关的导航/续接不会取得报告权限；换会话、重启或 `/reload` 仍须重新连接。

**旧版已误判失败的轮次不会自动复活。** 更新代码不会改变已加载的扩展或历史记录。
先核实原 Pi 及其子任务已结束，再将项目加载入口指向新版，手动 `/reload`、明确重新连接并重新分配。
若只是补录已有成果，可在工作台 `b` 中明确写“仅核对并补录已有阶段交付，不修改文件、不重跑工作、不启动实验”，
核对派发确认框后再 `s` 建立新的报告轮次。它仍会调用所选 Pi，不能无确认自动执行；原失败记录保留。
不要编辑数据库/邮箱来伪造完成，也不要为了恢复进度直接重派原执行要求。

## 停止、退出与失联

- `x` 请求停止当前真实轮次，确认后先保存意图，再通知对应 Pi。
  **请求发出不等于已停止**，以 Pi 完全空闲的确认记录为准。
- 只停止仍能确认属于该任务的执行；若 Pi 正在确认输入归属、有未接收输入或已解除关联，不会为此终止可能无关的工作。
  这种情况请到原 Pi 核实和处理。执行过程中不要混入其他任务。
- 退出工作台**不会停止 Pi**。重开只恢复观察，不重发请求、不自动验收。
- 失联、旧心跳、未收到确认或桥接损坏都不代表已停止，不能直接重派。
  先在原 Pi 核实并停止旧执行及其可能的子进程；必要时退出旧 Pi。
  对未消费的派发请求，还须断开旧 Pi 并等待 30 秒过期。
  然后 `Ctrl+K` → **失联恢复**，明确确认并记录核实情况，才能解除旧轮次。
  该操作本身不停止进程、不自动重派。
- 桥接写盘故障、损坏或不兼容的请求会暂停该连接，保留已知记录及失败请求。
  修复磁盘也不会自动重试执行；不要删除 Run/邮箱来“重试”，先去 Pi 核实。

## 数据与隐私

```bash
just run --db '/absolute/path/task data/tasks.sqlite3'
# 不使用 just：
uv run --no-project --python python3 app.py
```

- 默认数据库：`~/.local/state/waggle/tasks.sqlite3`；绝对 `XDG_STATE_HOME` 可改变 state 根目录。
- 默认邮箱：同一 state 根下 `waggle/bridges/`。
  可设置绝对 `WAGGLE_BRIDGE_DIR`，但**工作台和 Pi 必须一致**；`--db` 不改变邮箱位置。
- `--demo` 与 `--db` 互斥；演示模式与真实任务不互相导入。
- 新建库目录/文件权限为 0700/0600；已有库权限不擅自修改。
  邮箱要求当前用户所有的 POSIX 私有普通目录/文件，拒绝符号链接、公开权限和不兼容记录。
- 邮箱不是不可信程序的沙箱：同一系统用户拥有本地访问权限。
  任务邮箱包含所派发任务的标题、说明、目录、会话 ID、原会话文件位置、报告快照和有界关键记录，不另行提取思考内容。
  关键记录不复制普通工具流水、成功日志或日常压缩过程；影响交付的失败和归属异常仍会记录。
  独立的 `activity.json` 只保留有界当前工具名称、调用标识、源时间和已关联后台执行的状态，不含参数、输出、任务文本或思考内容。
  可选 `session.json` 保存当前活动、关联轮次、输入待接收标记及源修订/时间，不写入 SQLite。`runs/<父 Run>.next.json` 保存不可变续接链接和新轮次的初始身份/要求，不复制普通聊天或工具流水。
  压缩交接时桥接只核对当前会话树中的相关工具回执、摘要和分支关系，不导出完整会话历史。
  **工作台新建 Pi 的原生会话**由 Pi 保存在 `bridges/launches/<创建 ID>/sessions/`，
  遵循 Pi 自身的保存规则，可能包含完整会话内容；这与工作台的有界进展记录不同。
  工作指令进入所选 Pi 的上下文，遵循该 Pi 的模型/提供方和数据处理配置。

每次明确提交成功立即保存。派发前先保存独立 Run UUID 和不可变任务输入，发布不代表确认；
同一 Run 不重复注入，也不在重启或超时后自动重试。每个 Pi 同时只接受一个本工作台轮次。
报告是 **Agent 自报**，工具“返回成功”也不是独立测试证明。只有人工验收动作会设为已验收。

### 存储恢复

- 未提交表单不是自动草稿。保存失败保留输入和原记录；故障解除后可重试保存。
- 并发窗口使用修订冲突保护：旧窗口不会覆盖新数据。
  先复制未提交文本，再关闭重开；不做多客户端实时同步/自动合并。
- 当前源码库格式为 v11：保留 v9 成果库存、人工核验与 v8 明确前序来源及所有旧历史，新增局部依赖、条件核对、原写者释放、独立接收及不可逆失效审计；Task/Run/报告/邮箱 wire 不变。
  已识别的 v1～v10 库只在单一事务中升级；只为旧版本缺少的 registry 留空，不猜关联、事实、核验、写者释放/接收或权限，不改原报告和人工验收字节。
  对应 `legacy_v1`～`legacy_v10` 表保留升级前原始修订与 JSON，已有备份不覆盖；不补造报告或历史时间。失败迁移原库保持不变。
  v10 旧依赖声明缺不可逆失效证明，旧核对/释放/接收原样保留但不可自动用于新操作；必须明确重新声明并核对，不猜测旧范围是否曾变化。
  这里只验证过隔离迁移，并未授权/执行真实升级。真实迁移须单独授权；升级前退出其他工作台窗口并另行备份。旧版程序会拒绝 v11 库，不应混用不同版本。
  这是结构迁移，不负责命名、加载入口或事件前缀迁移。v1 旧任务仍是模拟任务，不转成真实执行；新建任务可使用真实项目。
  旧样例目录不可用于真实派发，请另加真实目录。
- 异库、新版本、损坏或不兼容数据拒绝加载/覆盖；失败迁移回滚，不替换成空库或样例。
- 备份请先退出所有工作台并让相关 Pi 断开桥接，再复制数据库和需要保留的邮箱。
  无自动外部备份、无自动清理；不要在运行时手改数据。

v11 用 SQLite 事务保存完整任务/Run/补充/步骤/人工决定/选定来源及核验/依赖/交接审计快照，写入成本随总历史增长。
每份任务级或单轮关键记录最多 120 条，JSON 编码后的事件数组最多 384 KiB。
超过任一限制时保留原 Pi 定位和最近的报告快照，并提示“部分记录未保留”；不会截断报告快照来冒充完整内容。
报告正文/剩余项各最多 6000 字符，核实依据最多 32 条、每条 1000 字符；旧版已截短的记录无法还原。
完整工具过程仍查看原 Pi。关键记录仍沿用字符串列表及 v1 邮箱格式，不因打开旧库而改写历史或补造时间。
当前没有自动调度、旧 Board 导入、后台守护服务或其他 Agent 平台支持。

左右导航只在任务列表和详情区生效，不抢输入框、编辑器和弹窗的方向键。

`previews/` 是早期模拟版 SVG/终端文本，仅同步品牌文字，不是当前真实任务截图。

### 删除项目、任务与恢复

**Ctrl+K → 删除项目**：在具体项目下直接核对该项目；在全部项目/收集箱下先选择项目。
确认框列出项目名、精确目录和关联任务数。只删除工作台的登记，**绝不删除磁盘目录、代码、成果文件或 Pi 会话**。
任一关联任务仍在执行、排队、等待确认、停止未确认，或执行身份/结束状态不明时，整个项目都不能删除；不会先删掉其中一部分。
删除成功后，所有关联任务（含已归档、已在回收站的任务）归属收集箱并进入回收站，保留报告、历史轮次、验收状态及原项目名称/路径记录。
界面自动显示这些回收站任务。恢复任务后仍归属收集箱，不自动恢复项目登记；需要继续工作时另行安排项目。内置收集箱不能删除。

这里沿用现有的**回收站**存放待删除任务；**收集箱**仍表示尚未归入具体目录的任务，避免混淆两种用途。
选中任务，按 **Ctrl+K**：

- **删除任务 · 移入回收站**：未启动或已确认结束的任务都可使用，包括已归档任务。此时保留任务和全部现存历史，可恢复。
- **归档任务**：有执行历史且已确认结束时，保留结果、报告、轮次和验收状态，只从当前列表隐藏。
- **回收站 → 永久删除任务及历史**：再次核对并确认，删除当前工作台中的该任务、全部 Run、报告和关键记录；无法通过工作台恢复。
- **执行中或结束状态不明**：禁止删除、归档和永久删除。连接断开不算结束，也不能通过删除解除执行占用。

所有变更均须确认，默认聚焦“返回”；确认期间目标项目、任务或历史发生变化，或保存失败时，原记录和界面选择保持不变。
删除/归档前还须人工核实相关后台子任务已结束。操作不会停止进程、删除邮箱或派发新任务。

普通列表/看板、搜索和侧栏计数默认只包含当前任务。按 **f → 已归档 / 回收站**，或在 Ctrl+K 中选择对应查看入口。
这些视图保留项目和搜索条件，支持阅读详情及记录；要继续编辑、分配、派发、补充或验收，先 **Ctrl+K → 恢复任务**。
恢复不启动执行、不撤销验收，也不把阶段交付变成完整交付。任务 ID 在永久删除后也不会复用。

永久删除只清除当前工作台记录，不修改原 Pi 会话、迁移备份、外部备份和任何项目文件；不是敏感数据安全擦除或数据库瘦身。

### 概览与展开详情

首屏先回答：**谁在执行、本轮什么状态、最近有何实质更新、是否需要你操作**。标题区是任务状态，执行区是当前 Run 的状态，两者不混为一谈。
执行者名称只在身份可核对时显示；正常心跳不是任务进度。同一 Pi 转去其他执行、身份变化或连接异常时，只保留最后已知状态，不把它现在的忙碌算到原任务上。
排队表示已保存派发意图、等待回执；Pi 权限等待需要到原 Pi 处理；已请求停止不代表命令已送达或已经停止。
报告收到但执行未完全结束不能验收；阶段交付显示剩余事项；失败/中断显示已知原因或完整原因入口，而非缺少简报的套话。
已验收任务不会因为原 Pi 后来离线而退回异常状态。权限等待、停止未确认、连接异常也会显示在固定的底部提示行，阅读长正文时仍可看到。

未验收任务的简要动作、交付和验证只采用执行者明确提交的 `brief`，标明自报；没有简报时提示打开已保存的完整报告。
**已验收任务默认展示“已完成”和“验证依据”**：优先使用匹配最终报告的简报；没有有效简报时，将已保存的最终交付正文按原有非空行列成完成项，已有列表标记不重复添加，验证依据沿用原有展示。不截取长文或生成总结，完整原文与换行仍保留在详情。缺失的内容明确标为未保存，不推断验证通过；过程、范围与技术标识仍放在详情。
有简报时按“交付结果 → 已完成 → 验证依据”分区；章节标题使用高对比底色与粗体，正文使用常规字重，段落与证据项之间留白。
正常执行且尚无报告时不重复空报告、空证据、未知剩余的警告；有实际报告或异常才展示相应内容。
“最近”使用关键记录的源时间，不以心跳补造进度时间；完整报告的源时间仍在详情中。
任务列表仅保留项目与可用的执行者名称；模型和连接 ID 放到展开详情，缺失的执行者名称不以 UUID 填满列表。

点 **展开详情**，在同一任务面板查看完整动作、交付正文、核实依据、阻塞/读取异常原因与剩余限制，保留换行和全部已保存内容。
任务说明与本轮补充要求分别展示；真实执行使用派发时固定的范围，退回后则展示下一轮待派发要求。
派发要求不是执行者自报的剩余工作，也不自动当作阻塞。
点 **收起详情** 返回概览。重新打开或切换任务默认收起，普通进展刷新保留展开状态和阅读位置。
退回后的上轮成果只在记录里作为历史，不显示成下一轮交付。尚未派发新轮时，首页仍只读列出对应已结束轮次的剩余/待确认事项，标明“历史自报，不构成批准”；已保存的新要求另列为“待派发请求（未发送）”。旧文字不会生成正式决策记录，保存整理请求也不等于 Agent 已整理或任务已启动。
人工验收仍单独核对完整交付、范围与证据；完整报告还须执行完全结束、无剩余项，确认框默认“返回”不变。

派发说明会要求 `waggle_report` 提供简报；该参数仍可省略，但报告必须使用新的工具名：
- `brief.actions`：1～3 条具体动作，每条最多 100 字符。
- `brief.outcome`、`brief.verification`：各最多 160 字符；未运行/未验证必须说明，不能把剩余工作藏到简报里。
- `summary` 仍为完整报告，`checks` 仍为具体依据，`remaining` 仍单独填写；简报不替代这些字段或验收条件。

### 当前活动：独立的可选快照

- Pi 的真实工具开始/结束事件提供名称与源时间；显示最近工具返回失败，不等于判定整个 Run 失败。工具之间未上报的步骤不猜成“思考中”、卡住或进度百分比。
- 后台观察目前支持 `pi-subagents` 的创建调用：只采用本轮实际工具返回且一致的 `asyncId` / `runId`，再用公开 v1 只读 status RPC 核对这些 ID。管理/status 调用的结果不会收编为本任务的后台工作，也不按同会话的名称、忙碌状态或总数猜归属。
- 后台查询按本轮至少间隔 5 秒节流，3 秒未回、协议不兼容或投影中缺失该 ID 均显示未知。只显示后台执行的生命周期状态，不是进程退出证明；不读取子任务的输出或会话文件，不发起新执行或控制请求。
- 前台子任务、其他委派工具、没有关联回执的工作及深层子进程不在此后台观察范围。没有后台条目不代表没有后台工作，不能据此推断全部完成。
- 每个连接只有一份当前 `activity.json`：最多 8 个当前工具、最近一次工具返回和 8 个后台执行，16 KiB 上限；超限明确显示只保留部分活动。它不写入 SQLite 或关键记录，不形成工具流水档案。
- 快照严格绑定 Run / Agent / Session / 精确目录，并检查递增修订。观测超过约 10 秒、读取异常、修订倒退或归属失效时不显示为当前工具；有旧观测则保留其时间。心跳更新观察时间，不改变工具的开始/结束时间。
- 工作台只读取选中任务的活动；状态更新不重建长报告或移动按钮。切换任务后到达的旧读取结果丢弃；展开、记录和查看状态不派发、不重新连接、不验收。

活动文件失败只影响可选观察，不暂停正常的任务报告；旧桥接没有该文件时显示“当前步骤未上报”。活动快照本身不改变 Run/Agent v1 格式或历史数据；当前 v11 库升级见“存储恢复”；活动快照仍不入库。
报告、Pi 主执行的 `agent_settled` 水位与人工验收仍独立；后台状态不参与现有机器验收门槛，Pi 主回合空闲也不证明所有派生进程已退出，仍需人工核实。
新版桥接代码只在后续明确加载后生效；等旧任务及相关子进程结束后再手动更新/连接，不为补齐实时信息重派旧任务，也不自动重载正在运行的 Pi。

### 任务记录：看关键变化，不复制工具流水

点 **记录**，或 `Ctrl+K → 任务记录`。按执行轮次分组，最新轮次默认展开，较早轮次折叠；
创建、编辑、分配等未绑定某次执行的操作单列为任务级记录，不猜测旧记录属于哪一轮。
保留派发、确认开始、进展/阶段/完整报告、等待确认、失败与交付失效、停止、退回和人工验收。
普通工具开始/成功、闲聊、心跳与正常压缩过程不进入新版任务记录；旧版工具流水也不在此视图展示，没有额外的诊断日志页。

选中一份新报告，看到的是**当时保存的完整快照**，不是最新结果的别名。
旧报告只能展示当时留下的摘录，并明确说明缺少快照、依据或剩余项；选择轮次标题可另看“该轮最后保存的结果”。
时间由事件产生端记录为 UTC，显示为本地时间和时区；旧记录显示“时间未知”，不拿刷新、文件或任务更新时间补填。
轮次内按事件修订和人工操作的观察位置排列，最新在前；时间不决定顺序、状态或验收。

单击轮次分组的箭头或标题可展开/收起；单击具体记录查看正文。`↑↓` 选择记录，`Enter`/空格展开或折叠轮次，`Tab` 切到正文滚动。
宽屏左右分栏，窄屏上下排列。`Esc` 返回后保留详情展开状态、滚动和焦点；查看期间使用打开时的快照，不随后台更新跳动。
记录只读，没有验收或重派操作。

### 原 Pi 会话：只提供定位，不切换会话

在任务记录中选中一个轮次或其事件，点 **原 Pi 会话**。
只检查派发时保存的原会话文件头（最多 16 KiB），核对 Session ID、精确目录、普通文件与当前用户所有权；不读取对话正文。
显示原目录、Session、会话文件和 `RUN_ID=<执行 UUID>`。同一 Session 可能执行多个任务，应按 RUN_ID 找原任务消息，而不是跳到执行者现在的会话。
原文件缺失、位置未知或校验失败会明确提示，不扫描其他会话，也不恢复、切换、新建或发送任务。
需要时自行在原 Pi 中核对 `/session` 并搜索 RUN_ID；`/tree` 选择条目会改变对话位置，仅查看时用 Esc 返回。

同一 Waggle 命名与数据目录内，正常升级不需要重跑任务；缺失的时间、简报、历史快照和原会话位置不会补造。
**本次更名不属于这种兼容升级**：旧数据和桥接入口请按“命名与升级边界”处理，不会自动迁移或接管。
新增人工操作由新版工作台记录时间；新报告快照、简报与原会话位置需要新版桥接在后续执行时保存。
已有 Pi 请等本轮及相关子任务结束、并完成入口切换后，再手动 `/reload`、明确连接；不要为了补齐历史信息重派旧任务。

## 一键本地打包

在 **Waggle 仓库目录**执行（不是 Herdr 仓库的发布命令）：

```bash
just package
# 不需要 uv 或 just 的等价命令：
python3 release.py

python3 release.py --list                    # 只预览收集清单，不生成包
python3 release.py --output /你的打包输出目录
```

打包工具只需要 **Python ≥3.11 和 Git**。默认在 `dist/` 生成独立的带时间/随机后缀目录，内含 `.tar.gz` 和外部 `SHA256SUMS`。
它只做本地打包，不提交、不打 tag、不推送、不安装依赖、不连接或重载 Pi。可以在未提交的工作区执行；复制当前磁盘内容，不用 `git archive HEAD`。

文件选择由 `release-files.txt` 白名单和 Git 忽略规则共同决定：匹配的已修改文件、未跟踪新模块和嵌套源码都会收集，已删除文件不会从 HEAD 复活。
`.pi`、`.local`、虚拟环境、缓存、数据/邮箱/会话、旧截图和生成的 `dist` 不进入包；即便被强制跟踪也不会收集这些私有路径。链接与非普通文件会拒绝。
新增其他类型的公开资源时显式更新白名单；它不代替源码中的密钥审查，不应把凭据写入源码。

包内提供 `run.sh`、`pi.sh`、`DEPLOY.md`、来源清单及逐文件校验。`requirements.txt` 每次从最新 app.py 的 PEP 723 声明生成，不维护第二份手写版本号。
启动器优先用 uv；没有 uv 时使用包内 `.venv/bin/python` 或 PATH 中的 python3，缺少依赖会提示手动安装，不会自动修改全局环境。
完整无 uv 部署步骤见 [DEPLOY.md](DEPLOY.md)。

打包前会检查必要入口、Python 语法、依赖声明和源文件是否在收集期间变化；失败不发布半成品，已有输出不覆盖。当前源码包上限为 1000 个文件、单文件 2 MiB、总量 16 MiB。
**打包成功不等于测试通过**：工具不执行项目或完整测试，清单明确标记 `tests: not_run`。需要质量验证时先运行下面的测试；原生 Herdr pane 烟测仍须单独明确执行。
默认 `dist/` 已忽略；使用自定义输出位置时，也应把生成物放在源码之外或纳入忽略规则。
